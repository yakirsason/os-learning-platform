**דוגמה - מה קורה כשמריצים <code dir="ltr">rm file.txt</code>?**

1. המשתמש מקליד את הפקודה ב-<code dir="ltr">bash</code>.
2. ה-shell מפרק: פקודה = <code dir="ltr">rm</code>, ארגומנט = <code dir="ltr">file.txt</code>.
3. ה-shell טוען את <code dir="ltr">/usr/bin/rm</code> לזיכרון.
4. <code dir="ltr">rm</code> מבצע <code dir="ltr">unlink("file.txt")</code> - קריאת מערכת.
5. הגרעין מוחק את הכניסה של הקובץ ממערכת הקבצים.
6. <code dir="ltr">rm</code> מסיים, השליטה חוזרת ל-shell.

### הדמיה: מעבר בין User Mode ל-Kernel Mode

**מה לראות:** כש-<code dir="ltr">printf()</code> נהפך ל-<code dir="ltr">write()</code>,
מעקב אחר ה-Mode Bit שמתחלף 1→0→1 ואחר התנועה של ה-token בין ה-lanes.

**למה זה חשוב:** זו התשתית של כל הגנה וכל אבטחה במערכת. לחצו על כפתור הניסוי בתחתית כדי לראות מה קורה כשתוכנית מנסה להפעיל הוראה privileged מ-user mode.

### דוגמה: <span dir="ltr">printf → write</span>

כשמפעילים <code dir="ltr">printf("Hello")</code>:
1. <code dir="ltr">printf()</code> ב-<code dir="ltr">libc</code> מפרק את ה-format string.
2. הוא קורא ל-<code dir="ltr">write(1, "Hello", 5)</code> - קריאת מערכת ל-STDOUT.
3. <code dir="ltr">write()</code> מפעיל trap → מעבר ל-kernel mode.
4. הגרעין מעתיק את המחרוזת ל-buffer של הטרמינל.
5. השליטה חוזרת ל-<code dir="ltr">printf</code>, שחוזר לקוד המשתמש.

## Policy vs Mechanism ⭐

אחת ההפרדות החשובות בעיצוב מערכות הפעלה - **מה** לעשות מופרד מ-**איך** לעשות.

<div className="my-4 grid gap-3 md:grid-cols-2">
  <ConceptCard
    title="מנגנון"
    englishTerm="Mechanism"
    description="ה'איך' - הכלים והמבנים שמאפשרים לבצע פעולה. קבוע, יציב, לרוב בחומרה."
    variant="info"
  />
  <ConceptCard
    title="מדיניות"
    englishTerm="Policy"
    description="ה'מה' - ההחלטה מתי ואיך להשתמש במנגנון. יכולה להשתנות מאתר לאתר, ממשתמש למשתמש."
    variant="info"
  />
</div>

<StudyCallout variant="oneliner">
  <strong>Timer</strong> הוא מנגנון: החומרה יודעת לצלצל אחרי N ms.
  <strong className="px-1">Quantum</strong> הוא מדיניות: ה-OS מחליט כמה זמן
  לתת לכל תהליך. שינוי quantum → התנהגות שונה, אבל אותו timer.
</StudyCallout>

### הדמיה: Policy מול Mechanism בפעולה

**מה לראות:** ה-timer (מנגנון) מתקתק ללא הפסקה על צד ימין. ה-quantum (מדיניות)
נקבע על ידי הסליידר בצד שמאל. כשמשנים את ה-quantum - דפוס ה-Gantt משתנה, אבל
ה-timer בדיוק כמו שהיה.

**למה זה חשוב:** הפרדה נכונה בין policy ל-mechanism מאפשרת להחליף policy
(לדוגמה, לעבור מ-Round Robin ל-Priority Scheduling) בלי לשנות את הגרעין.

        התקתוק לא משתנה.
      </p>
      <p className="mt-2">

## מבני מערכות הפעלה ⭐

יש שישה מבנים אדריכליים עיקריים. כל אחד מפשר בין **פשטות, ביצועים, אמינות
וגמישות** בצורה שונה.

<StudyCallout variant="compare" title="5 המבנים הקלאסיים">
  <div className="space-y-1.5 text-xs">
    <div><strong>Simple</strong> — הכל ברמה אחת. <span className="text-muted-foreground">(MS-DOS)</span></div>
    <div><strong>Monolithic</strong> — גרעין ענק אחד. <span className="text-muted-foreground">(UNIX מסורתי)</span></div>
    <div><strong>Layered</strong> — שכבות, כל אחת משתמשת רק בתחתונה ממנה. <span className="text-muted-foreground">(THE System)</span></div>
    <div><strong>Microkernel</strong> — kernel קטן + שירותים ב-user space. <span className="text-muted-foreground">(Mach, QNX)</span></div>
    <div><strong>Modular</strong> — kernel בסיסי + modules טעינים דינמית. <span className="text-muted-foreground">(Linux LKM)</span></div>
  </div>
</StudyCallout>

### הדמיה: חמישה מבנים, אותה בקשה

**מה לראות:** כיצד בקשה של <code dir="ltr">read()</code> זורמת דרך כל מבנה.
שימו לב לאורך הנתיב ולנקודות החולשה השונות.

**למה זה חשוב:** זה מסביר למה macOS יציב (microkernel core) אבל פחות מהיר
מ-Linux (modular monolithic). בחירות אדריכליות = tradeoffs אמיתיים.
